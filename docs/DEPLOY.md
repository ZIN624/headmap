# 公開ガイド

**日本語** | [繁體中文](DEPLOY.zh-Hant.md) | [English](DEPLOY.en.md)

「カット図 3D」を自分のサイトとして公開する手順です。プログラミングの知識は不要で、選んだサービスの手順どおりに進めれば公開できます。

## はじめに知っておくこと

1. **完全な静的サイトです。** サーバー側のプログラム・データベース・ビルド・パッケージのインストールはありません。このフォルダのファイルをそのまま Web ページを配信できる場所に置けば公開されます。
2. **描いた図は使う人のブラウザの中に保存されます。** ホスティング側に図が届くことはなく、保存場所を用意する必要もありません。
3. **データはアドレスごとに分かれます。** `a.example.com` で描いた図は `b.example.com` では見えません。人に使ってもらう前にアドレスを決めてください（[アドレスを変えるとき](#アドレスを変えるとき)）。

サイト全体は約 9 MB で、そのうち 4 種類のヘッドが約 6 MB です。

## サービスを選ぶ

| サービス | 料金 | 向いている人 | GitHub アカウント |
|---|---|---|---|
| [Cloudflare Pages](#cloudflare-pages) | 無料 | ほとんどの人。元のサイトもこれで動いています | 必要（ファイルを直接アップロードする方法もあり） |
| [GitHub Pages](#github-pages) | 無料 | すでに GitHub を使っている人 | 必要 |
| [Netlify](#netlify) | 無料枠あり | ドラッグ＆ドロップでアップロードしたい人 | どちらでも |
| [Vercel](#vercel) | 無料枠は個人・非商用のみ | すでに Vercel を使っている人 | 必要 |
| [自前のサーバー](#自前のサーバー) | サーバーによる | サーバーやドメインを持っている人 | 不要 |

上の 4 つは無料の HTTPS アドレスが付きます。管理画面は時々変わるので、ボタン名が少し違うときは一番近い意味のものを選んでください。

## コードを用意する

- **フォーク（おすすめ）：** <https://github.com/zin624/headmap> の右上の **Fork** を押すと、自分用のコピーができます。
- **ZIP でダウンロード：** 同じページの **Code → Download ZIP** で取得して展開します。GitHub と連携せずにファイルをアップロードしたい場合はこちら。

## Cloudflare Pages

1. このリポジトリをフォークします（自分のリポジトリならそのままで構いません）。
2. [Cloudflare](https://dash.cloudflare.com/) にログインし、**Workers & Pages** → **Create** → **Pages** タブ → **Connect to Git** を開きます。
3. Cloudflare に GitHub の読み取りを許可し（このリポジトリだけに限定できます）、リポジトリを選びます。
4. 設定を入れます。

   | 項目 | 値 |
   |---|---|
   | Project name | 好きな名前。アドレスは `プロジェクト名.pages.dev` になります |
   | Production branch | `main` |
   | Framework preset | `None` |
   | Build command | 空のまま |
   | Build output directory | 空のまま（リポジトリのルート） |

5. **Save and Deploy** を押します。1 分ほどで `https://プロジェクト名.pages.dev/` が公開されます。

以降は `main` に新しいコミットが入るたびに自動で公開し直されます。

**GitHub を使わない場合：** 手順 2 で **Upload assets** を選び、プロジェクト名を付けて、展開したフォルダをドラッグします。更新するときはもう一度アップロードします。

リポジトリの `_headers` は Cloudflare Pages が読む設定ファイルです。ライセンス文（`LICENSE`）をテキストとして表示し、サイトのアドレスがリンク先に送られないようにしています。そのままにしてください。

## GitHub Pages

1. このリポジトリをフォークします。
2. リポジトリの **Settings** → 左の **Pages** を開きます。
3. **Build and deployment** の **Source** を **Deploy from a branch** にし、**Branch** を `main`、フォルダを `/ (root)` にして **Save** を押します。
4. 1〜2 分で同じページの上にアドレスが出ます：`https://アカウント名.github.io/リポジトリ名/`。

注意：

- `.nojekyll` は GitHub にファイルをそのまま配信させるためのファイルです。消さないでください。
- GitHub Pages では「このアプリとライセンス」のライセンス全文のリンクが、表示ではなくダウンロードになることがあります。アプリの動作には影響しません。
- `アカウント名.github.io` の下のサイトはブラウザの保存領域を共有します。同じアカウントにこのアプリを 2 つ置くと、同じライブラリを読みます。

## Netlify

**GitHub から：** [Netlify](https://app.netlify.com/) にログイン → **Add new site** → **Import an existing project** → GitHub とリポジトリを選ぶ → **Build command** は空、**Publish directory** は `.`（または空）→ **Deploy**。

**ドラッグ＆ドロップ：** <https://app.netlify.com/drop> を開き、展開したフォルダをドラッグします。

`_headers` は Netlify でも有効です。

## Vercel

[Vercel](https://vercel.com/) にログイン → **Add New… → Project** → リポジトリを読み込む → **Framework Preset** を **Other** にし、**Build Command** と **Output Directory** は指定しない → **Deploy**。

Vercel の無料（Hobby）プランは個人・非商用のみです。お店や会社で使う場合は有料プランか、ほかのサービスを使ってください。

## 自前のサーバー

このフォルダのファイルをすべて Web のルートに置き、静的ファイルとして配信します。例を 2 つ挙げます。

**Caddy**（HTTPS の証明書を自動で取得します）：

```
headmap.example.com {
    root * /var/www/headmap
    file_server
}
```

**nginx：**

```nginx
server {
    listen 80;
    server_name headmap.example.com;
    root /var/www/headmap;
    index index.html;

    # ファイル名にバージョンが付かないので、毎回確認させて更新がすぐ反映されるようにする
    add_header Cache-Control "no-cache";
    add_header Referrer-Policy "no-referrer";

    location = /LICENSE { default_type text/plain; }
    # git clone で置いた場合は .git フォルダを配信しない
    location ~ /\.git { deny all; }
}
```

注意：

- **HTTPS にしてください。** HTTPS でないアドレスでは「ホーム画面に追加」やスマホの共有・写真に保存が使えません（`localhost` は例外）。
- **`index.html`・`style.css`・`src/` に長いキャッシュを設定しないでください。** ファイル名にバージョンが付かないので、古い版が表示され続けます。
- `.js` は JavaScript の種類（`text/javascript` か `application/javascript`）で配信する必要があります。通常の Web サーバーは最初からそうなっています。`.glb` と `.webmanifest` の種類は不明のままでも動きます。
- `server.mjs` は手元確認用の小さなサーバーです。一般公開には上のサービスか通常の Web サーバーを使ってください。同じ Wi-Fi のスマホで一時的に試すなら `node server.mjs --lan` を使います。

## 公開したら確認すること

1. アドレスを開き、「ヘッドを読み込み中…」が消えるのを待ちます。
2. 右上の **＋** → **3D ヘッド**：ヘッドが表示され、髪の範囲をドラッグすると線が描けます。
3. ホーム画面に戻り、**2D 5方向** の図を追加：5 方向の下絵が表示されます。
4. ページを再読み込み：2 つの図が残っています。
5. ホーム画面の **⋯ → このアプリとライセンス**：ソースコードのリンクが正しいこと（次の章）。

## 自分用に変える場所

何も変えなくても動きます。変える場合はふつう次の場所です。

| ファイル | 変える内容 |
|---|---|
| `index.html` の上の方の `og:url` と `og:image` | 自分のアドレス。LINE や Facebook にリンクを貼ったときのプレビューに使われます |
| `index.html` の `<title>` と `description` | ページの名前と一行の説明 |
| `index.html` の「このアプリとライセンス」のソースコードのリンク | **コードを変えた場合は必須：** 自分の公開ソースに向けます（[ライセンス](#ライセンスagpl-30)） |
| `manifest.webmanifest` | ホーム画面に追加したときの名前（`name`・`short_name`）と色 |
| `icons/` | 192×192、512×512、180×180（`apple-touch-icon.png`）の 3 つのアイコン |
| `assets/heads/heads.json` | `default`＝新しい 3D の図で使うヘッド、`default2d`＝2D で使うヘッド |

ヘッドの基準ポイントのデータ（`assets/heads/*.json`）を変えたら、`node tools/build-transfer.mjs` を実行してヘッド切り替えの対応点を作り直してください。

変更はまず手元で確認します：`node server.mjs` で <http://127.0.0.1:8080/> を開き、`npm test` を実行します。

## ライセンス（AGPL-3.0）

プログラムは [AGPL-3.0](../LICENSE) で公開されています。かみくだくと：

- 無料で使う・変える・公開することができます。仕事で使っても構いません。
- **変えずに公開する場合：** 「このアプリとライセンス」の元のソースコードのリンクを残せば十分です。
- **変えたものをネットワーク経由でほかの人に使ってもらう場合：** 利用者がその版のソースコードを AGPL-3.0 で入手できるようにする必要があります。いちばん簡単なのは、フォークを公開リポジトリにして「このアプリとライセンス」のリンクをそこに向けることです。
- `LICENSE`、著作権表示、外部素材のライセンスファイル（`assets/heads/licenses/` と `vendor/` の各フォルダの `LICENSE`）は **消さずに残してください**。

これは理解を助けるための要約で、法的な助言ではありません。`LICENSE` の全文と違う点があれば全文が優先されます。

## 更新するとき

- **フォークの場合：** リポジトリのトップで **Sync fork → Update branch** を押します。Cloudflare Pages・GitHub Pages・Netlify・Vercel は自動で公開し直されます。同じファイルを自分でも変えている場合は、先に競合の解消を求められます。
- **アップロードした場合：** ZIP をもう一度ダウンロードしてアップロードし直します。
- **自前のサーバー：** サイトのフォルダで `git pull` するか、ファイルをコピーし直します。

更新しても、使う人の図には影響しません（各自のブラウザに保存されているため）。

## アドレスを変えるとき

ライブラリはアドレスごとに保存されます。ブラウザにとっては次のどれも別のアドレスで、変更後は空のライブラリで開きます。

- `プロジェクト名.pages.dev` から自分のドメインに移る
- `http://` から `https://` に変える
- サブドメインやポートを変える

変える前に、使う人に古いアドレスのホーム画面で **⋯ → すべてのカット図を書き出す** を選んでもらい、新しいアドレスの同じメニューで **JSON を読み込む** を選んでもらってください。できれば、広める前にアドレスを決めておきましょう。

## うまくいかないとき

**「ヘッドを読み込み中…」のまま進まない、または「ヘッド一覧が読めません」と出る**
`assets/heads/` のファイルがすべてアップロードされていない（4 つの `.glb` で約 6 MB）か、`index.html` をブラウザで直接開いています。Web サーバー経由（`http://` か `https://`）で開く必要があり、`file://` では動きません。

**真っ白なページになる**
F12 を押してコンソールを見てください。モジュールの MIME タイプのエラーなら、サーバーが `.js` を JavaScript として配信していません。import maps のエラーならブラウザが古すぎます（Chrome / Edge 89、Safari 16.4、Firefox 108 以上が必要）。

**更新したのに古い版が表示される**
サーバーや CDN のキャッシュが切れていません。まず強制再読み込み（Ctrl+Shift+R）を試し、自前のサーバーならキャッシュの設定を確認してください（[自前のサーバー](#自前のサーバー)）。

**iPhone・iPad で図が消えた**
ホーム画面に追加していないサイトは、Safari を使っている間に 7 日間開かないと保存データが消されます。共有メニューから「ホーム画面に追加」してもらい、大事な図は定期的に書き出してもらってください。

**ライセンス全文のリンクを押すとファイルがダウンロードされる**
サーバーが `LICENSE`（拡張子なし）をテキストだと認識していません。Cloudflare Pages と Netlify は `_headers` で対応済みです。ほかのサービスでは自分で設定するか、そのままにしてください。

**使う人が描いた図を見られますか？**
見られません。このアプリにはサーバー側のプログラムがありません。図はそれぞれのブラウザの中だけにあり、本人がファイルを書き出して送らない限り届きません。
